01 / THE IDEA

Make incident workflows more useful.

ResolveAI brings ticket and incident workflows together with AI analysis in one full-stack platform. The engineering focus is on connecting a usable interface to services with well-defined behavior.

I designed the ticket and AI-analysis APIs with explicit data models, validation, exception handling, and health monitoring. The architecture separates the interface, core services, AI workflows, and persistence so each layer has a clear responsibility.

02 / THE ARCHITECTURE

Four layers.
Clear boundaries.

  • Interface — React & TypeScript. The user-facing layer for end-to-end ticket and incident workflows.
  • Core services — Java & Spring Boot. REST endpoints, domain models, validation, and exception handling.
  • AI services — Python, FastAPI & LangGraph. RAG workflows with semantic retrieval and structured model responses.
  • Persistence — PostgreSQL & NoSQL access. Storage and data-access patterns designed for high-throughput workloads, with Docker for containerized services.

03 / ENGINEERING DETAILS

Reliability is part
of the design.

Two model-provider paths

The AI workflows support OpenAI and Ollama. The model-provider boundary is separate from the core ticket services, keeping provider-specific behavior within the AI layer.

Structured outputs, guardrails & fallbacks

LangGraph and RAG workflows use semantic retrieval, structured outputs, and guardrails, with deterministic fallback behavior to support resilient service operation.

Validation, monitoring & testing

Ticket and AI-analysis APIs include validation, exception handling, and health monitoring. JUnit and Postman support end-to-end testing across the workflows.
